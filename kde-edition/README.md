# ProtoOS KDE Edition — проект первой графической версии

Цель — **Debian Live VHD для Hyper-V Generation 2** с рабочим столом KDE Plasma. Сессия автоматически запускается под пользователем `protoos`; это Live-режим, поэтому пользовательские изменения сбрасываются при выключении ВМ.

## Дизайн: ProtoOS Aurora

Оформление вдохновлено ясной, аккуратной настольной эргономикой: тонкая верхняя панель, центрированная плавающая панель приложений, скруглённые окна, мягкие тени и спокойные градиенты. Это самостоятельный стиль ProtoOS — без логотипов, названий, иконок или иных ресурсов Apple/macOS.

В сборку входят две переключаемые цветовые схемы:

- **ProtoOS Aurora Light** — светлые поверхности, синие акценты;
- **ProtoOS Aurora Dark** — тёмный "glass"-интерфейс, индиго/лавандовые акценты.

По умолчанию выбирается тёмная тема. Пользователь сможет сменить её в **Системные настройки → Цвета**.

## Первый запуск и ежедневные задачи

В первом месте док-панели находится **Начать работу**. Это локальный помощник без интернет-страницы и телеметрии: через него можно открыть Proton Browser, файлы, «Документы», снимок экрана, сеть или оформление, а также увидеть важные горячие клавиши и объяснение Live-режима.

В сессии уже есть понятные роли для обычных задач: браузер, файлы, текст, документы, изображения, снимки экрана и архивы. Папки `Desktop`, `Documents`, `Downloads`, `Pictures` и другие XDG-папки создаются в каждом новом Live-доме. Терминал остаётся доступен, но не требуется для этих сценариев.

## Важные ограничения первой версии

- Цель — Hyper-V Generation 2, `x86_64 UEFI`.
- В качестве первой сессии используется **Plasma X11**: для виртуальной графики Hyper-V это более консервативный вариант, чем Wayland. Wayland можно добавить позднее.
- Сеть, установка на диск, обновления и сохранение изменений не входят в первый Live-релиз.
- Для комфортной работы ВМ потребуется не менее 4 ГБ ОЗУ. Рекомендуемый размер будущего системного VHD — 20 ГБ.

## Содержимое

- `manifest/packages.txt` — набор Debian-пакетов для Plasma Live-системы;
- `rootfs/etc/sddm.conf.d/10-protoos-autologin.conf` — автоматический вход в Plasma;
- `rootfs/etc/skel/` — начальные настройки, XDG-папки и параметры панели;
- `rootfs/usr/local/bin/protoos-welcome` — локальный двуязычный помощник первого запуска;
- `rootfs/usr/local/share/applications/` — краткие ProtoOS-роли для повседневных задач;
- `branding/` — обои, цветовые схемы, look-and-feel и оригинальные иконки ProtoOS Aurora;
- `third-party/Proton-browser.md` — источник, целостность и условия встраиваемого Proton Browser;
- `DESIGN_DIRECTION.md` — утверждённое направление ProtoOS Aurora и ограничения производительности Hyper-V;
- `concepts/protoos-aurora-performance-desktop.png` — визуальный концепт Aurora Performance;
- `scripts/provision-rootfs.sh` — воспроизводимый скрипт настройки уже подготовленного Debian rootfs.

## Сборочная граница

В текущем sandbox нет `debootstrap`/`mmdebstrap`, Docker/Podman, SquashFS-инструментов или доступа к зеркалу пакетов Debian. Поэтому этот коммит создаёт готовую конфигурацию и assets KDE Edition, но не выдаёт притворный VHD без настоящего Debian/Plasma userspace.

## Автоматическая сборка VHD

Полная KDE-система строится в GitHub Actions, где доступно официальное зеркало Debian и привилегированные инструменты разметки диска. Запустите workflow **Build ProtoOS KDE Hyper-V VHD** вручную на ветке ProtoOS. Он:

1. разворачивает Debian `trixie` в GPT-диске;
2. устанавливает KDE Plasma, SDDM, Linux kernel и GRUB EFI;
3. применяет ProtoOS Aurora, автоматический вход и ephemeral `/home/protoos`;
4. создаёт динамический VHD с виртуальной ёмкостью 12 ГиБ;
5. публикует VHD и SHA-256 как artifact GitHub Actions на 14 дней.

Локальный запуск того же процесса возможен только на привилегированной Debian/Ubuntu-машине с доступом к репозиториям Debian:

```sh
sudo ./kde-edition/scripts/build-hyperv-vhd.sh
```

После успешной CI-сборки VHD необходимо подключить к **Контроллер SCSI** в Hyper-V Generation 2, отключить Secure Boot и проверить появление рабочего стола Plasma.
