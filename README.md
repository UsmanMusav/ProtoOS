# ProtoOS Live

**ProtoOS** — учебная минимальная Live-система на Linux для `x86_64`. Первый выпуск (`0.1.0`) загружается в оперативную память, запускает BusyBox и даёт интерактивную консоль. На диск гостевой машины ничего не устанавливается.

> Это ранняя тестовая сборка, а не система для повседневного использования или хранения данных.

## Что уже работает

- загрузка через **UEFI** с ISO-образа;
- Linux-ядро с EFI stub;
- initramfs в памяти: BusyBox, `/proc`, `/sys`, `/dev`;
- консоль `ProtoOS#` и команды `help`, `sysinfo`, `uname -a`, `poweroff`;
- сборка ISO одним вызовом `make iso` без GRUB, xorriso или mtools.

Загрузчик UEFI в `boot/loader.c` — собственный маленький chain loader. Он загружает EFI-stub ядра и передаёт ему initramfs. Образ создаётся штатным Python-скриптом, который формирует FAT16 El Torito и ISO-9660 напрямую; поэтому сборочный процесс не зависит от утилит для записи ISO.

## Быстрый старт для тестера: Hyper-V

1. Возьмите файл `dist/ProtoOS-0.1.0-x86_64.iso` из готовой сборки или выполните сборку ниже.
2. В **Диспетчере Hyper-V** создайте виртуальную машину **поколения 2** (Generation 2).
3. Выделите от 512 МБ оперативной памяти; виртуальный диск не нужен.
4. В разделе **SCSI Controller → DVD Drive** подключите ISO.
5. В **Security** снимите флажок **Enable Secure Boot**.
   - Образ намеренно не подписан Microsoft ключом: Secure Boot остановит экспериментальную сборку до запуска.
6. Запустите ВМ. На экране должны появиться строки `ProtoOS Live 0.1.0`, затем приглашение `ProtoOS#`.

Первые команды для проверки:

```sh
help
sysinfo
uname -a
cat /etc/os-release
ls /
poweroff
```

## Сборка

Требования на машине сборки:

- Linux `x86_64`;
- `python3`, `gcc`, GNU `ld`, GNU `objcopy`, `git`;
- статический BusyBox по пути `/usr/bin/busybox`.

```sh
make iso
make check
```

Готовый ISO появится здесь:

```text
dist/ProtoOS-0.1.0-x86_64.iso
```

`make check` не запускает виртуальную машину, но проверяет ISO-9660, El Torito UEFI-элемент, FAT16 и наличие трёх обязательных файлов: `BOOTX64.EFI`, `KERNEL.EFI`, `INITRD.IMG`.

## Важное о ядре

Для первого загрузочного прототипа сборщик получает зафиксированный EFI-stub бинарник Linux из репозитория [RedMoonnn/MicroLinux](https://github.com/RedMoonnn/MicroLinux), commit `00a515d49c59f31c9c5e258928ac368012ac1ea6`, и сверяет SHA-256:

```text
dca8ba50d3ac9867073b54b7d694d019c9e048560102ddd4f9b2563df00686fd
```

Это временное решение, необходимое для быстрого тестового ISO в минимальной среде сборки. Оно **не является** утверждением о безопасности или происхождении этого бинарника. Следующая важная задача проекта — воспроизводимая самостоятельная сборка и обновление ядра из проверенного исходного кода, затем подпись Secure Boot.

## Что тестировать и как сообщать об ошибке

Пожалуйста, укажите:

1. версию Windows и Hyper-V;
2. поколение ВМ и состояние Secure Boot;
3. сколько памяти выделено;
4. фото/текст последней строки на экране;
5. получается ли набрать `sysinfo` после появления `ProtoOS#`.

Критический результат: чёрный экран, остановка до надписи `ProtoOS Live`, kernel panic или отсутствие ввода в консоли.

## Ограничения 0.1.0

- только `x86_64 UEFI` и Hyper-V Generation 2;
- только английская консоль и минимальный набор BusyBox;
- нет установки на диск, сети, графической оболочки, пользователей или сохранения данных;
- Secure Boot пока не поддерживается;
- запуск на физическом компьютере не является целью этой версии.

## План следующих итераций

1. подтверждение загрузки в Hyper-V и исправление найденных проблем;
2. собственная тема, `neofetch`-подобная системная информация и тестовые приложения;
3. сеть и пакетная структура пользовательского окружения;
4. графическая оболочка;
5. воспроизводимая сборка ядра и подписанный UEFI-образ.
